> 负责人 2026-08-15 指令：atlas-engine 生产的项目数据目录必须内置文档管理，不得重演早期图集的平铺乱象。
> 本档为强制规范；违反本档的目录 = 缺陷。
> **v2（2026-08-15 负责人令）：多项目宿主版式，见 §〇；下文 §一~§六 为 v1 单项目七区制条款**——
> v2 是 v1 的多项目宿主化演进（七区保留为共享区，隔离粒度下放到项目名），v1 条款在 v2 中的对应关系逐条注明。
> **v3（2026-08-16 负责人令）：门户伞目录版式，见 §〇-v3**——门户从根下平铺升为两级 `<伞名>/<伞名>-<YYMMDD>/`，
> 新增同名异路命名规则与机器可读项目注册表；§〇（v2）除门户路径结构外继续有效，冲突处以 §〇-v3 为准。

## 〇-v3、v3 门户伞目录版式（2026-08-16 负责人令）

> v3 在 v2 之上加「项目伞目录层」：门户从根下平铺 `<项目>-add-<YYMMDD>/` 升为两级
> `<伞名>/<伞名>-<YYMMDD>/`，并引入同名异路命名规则与机器可读项目注册表。七区隔离、P1-P6、
> 根 INDEX.md 文字正本地位全部不变。

### 〇-v3.1 三层结构（根 → 项目伞 → 期门户）

    <根>/
    ├── INDEX.md            文字正本（项目注册表，人类可读唯一入口）
    ├── index.html          根可视化索引 → 两级导航：项目伞 → 该伞下各期门户（build-portal --root 纯生成物）
    ├── demo-add/            ← 项目伞目录（umbrella）：一个项目（或该项目的一个源仓）一个伞
    │   ├── demo-add-260815/index.html    期门户（初始化/重扫各一期；旧期保留为历史，不删不覆盖）
    │   └── demo-add-260816/index.html
    ├── add-add/
    │   └── add-add-260815/index.html
    └── spec/ artifacts/ evidence/ data/ state/ rulings/ history/   七区不变（共享区）

- 伞目录名 `^(.+)-add$`；伞内只允许期目录 `<伞名>-<YYMMDD>/`（期名前缀与伞名强制一致），
  期目录须含生成式 index.html——违者（伞内其它条目/期名前缀不符/期缺 index.html）均为
  error `layout.portal`（lib/layout.mjs）；符号链接垫片一律跳过。
- 门户页相对链接深度 +1：`../../artifacts/...`、`../../evidence/...`（build-portal 生成，
  测试对全部 href/src 逐条 resolve 验存在）。

### 〇-v3.2 命名规则（含同名异路与「首个忽略路径」）

1. 伞目录名缺省 `<项目>-add`——**第一个出现的项目登记者不带路径段**（负责人原话
   「第一个出现忽略这个路径」）：首登记者即使给了 `--source` 也用缺省伞。
2. **同名但源路径不同的第二个项目** → 新伞 `<项目>-<路径简写>-add`：slug = 源路径父目录名
   清洗为 `[a-z0-9-]`（小写、非法字符折叠连字符）；被占用则自父目录向上追加一段连字符连接
   直到唯一；仍冲突追加路径 sha256 前 6 位 hex。占用 = 注册表已用伞名 ∪ 根下同名目录。
3. 期目录名 = `<伞名>-<YYMMDD>`（伞名前缀 + 6 位日期，前缀一致由校验器强制，见 〇-v3.1）。
4. 同源复用：已登记且 `--source` 与登记值相同（或未给 `--source`，或登记值为 null——null
   首次给出时补记，后续异路才能正确分流）→ 复用该伞；`--source` 与登记值不同 → 按 2 派生新伞。

### 〇-v3.3 机器可读项目注册表（state/projects.json）

放 state/ 区（根受 P1 禁平铺约束，注册表不落根）。形状：

    { "schemaVersion": 1,
      "projects": [ { "project": "demo", "umbrella": "demo-add", "sourcePath": null,
                      "firstSeen": "2026-08-16", "portals": ["260815", "260816"] } ] }

- 由 build-portal 读写：`--project` 登记/复用/派生伞并登记期（portals 去重升序）；
  坏 JSON **fail-loud**（exit 1，绝不静默重建）；文件缺失视为空注册表。
- 职责边界：注册表只管「伞 ↔ 项目 ↔ 源仓路径 ↔ 期清单」的机器真相；门户内容仍以
  artifacts/evidence 实扫为准；伞目录与源路径映射的正确性需外部真相，校验器列入 unchecked 具名披露。
- 校验器对齐顺序：伞名→项目段优先读注册表；注册表缺失/未登记该伞时回退「去掉 -add 后按
  连字符首段（边界前缀）匹配项目名」。

### 〇-v3.4 两级导航要求（根 index.html）

- 每项目卡片列该伞下**全部期**（日期倒序，最新一期标「最新」），链接
  `<伞名>/<伞名>-<日期>/index.html`（相对路径零拷贝）。
- 卡片显示：伞名、源仓路径（若登记）、期数、初始化（首期）与最近重扫（末期）。
- 七区地图 / 账本速览 / 页脚（生成时间戳 + 纯生成物声明 + INDEX.md 正本指引）照 v2 保留。

### 〇-v3.5 v2 → v3 兼容与迁移

- 根下 v2 平铺门户 `<项目>-add-<YYMMDD>` 照常被根索引收录（取最新一期，标注
  「v2 平铺门户（建议迁移）」），不报错。
- 校验器对 v2 平铺门户 = **warning**「v2 平铺门户已过时，建议迁入伞目录（见 atlas-layout v3）」
  不判 error（存量宽容，与 v1 legacy 同精神）；其结构校验（项目名在册、含 index.html）照跑。
- 迁移指引：对旧项目重跑 `build-portal --project <项目> [--source <源仓>]` 即按 v3 两级版式生成
  新期门户（旧 v2 平铺目录保留为历史，不删不覆盖）；存量数据迁移（历史期归位伞下）为独立一波工作，另行成文。

### 〇-v3.6 参照（成熟方案一行）

两级「伞 → 期」版式参照 mkdocs-mike 版本化文档站的 version-alias 布局（版本目录保留历史 + 顶层别名导航）。

## 〇、v2 多项目版式（2026-08-15 负责人令）

### 〇.1 版式总纲（三类内容，宿主唯一数据根）

一个数据根 = 一个宿主（平台/组织），根下三类内容：

1. **人类门户目录** `<项目>-add-<YYMMDD初始化时间>/`（如 `demo-add-260815/`）：专供人类访问
   html/png 的入口，内含生成式 `index.html`（scripts/build-portal.mjs 生成）。门户目录是**纯生成物，禁手改**；
   重扫门户 = 重建一个带新日期名的门户目录（重扫时间体现在目录名），旧门户目录可留作历史，不删不覆盖。
   **v3 修订（2026-08-16）**：门户升为两级 `<伞名>/<伞名>-<YYMMDD>/`（§〇-v3），本段单级形态降为
   存量兼容（校验 warning 提示迁移，不判死）。
2. **共享七区** spec/ artifacts/ evidence/ data/ state/ rulings/ history/（v1 §二 的七区保留为共享区）：
   - **spec/ evidence/ data/ 一级子目录 = 项目名隔离**：`spec/<项目>/<diagram-id>.json`、
     `evidence/<项目>/<diagram-id>/`、`data/<项目>/*.csv`（如 spec/demo/、spec/add/）；
   - **artifacts/ 两级 = 项目 / 模块-初始化时间**：`artifacts/<项目>/<模块>-<YYMMDD>/`
     （如 artifacts/demo/loops-260815/），模块目录名 = `<模块>-<YYMMDD>`（6 位日期）；
   - **state/ rulings/ history/ 跨项目共享**：账本隔离不靠目录，靠纪律——节点 id 以项目名前缀开头
     （P6 机器校验）+ 节点 owner 字段（记录区条目自带时间戳）。
3. **根 INDEX.md = 目录索引**（项目注册表）：项目 / 门户目录 / 初始化时间 / 重扫时间 / 图数 / 侧车指针。根另有生成式 index.html 可视化索引（build-portal --root 产物，纯生成物；INDEX.md 为文字正本）。

### 〇.2 隔离措施五条（成文强制）

1. **区内子目录**：spec/evidence/data 按项目名建一级子目录；artifacts 按 项目/模块-日期 两级；
2. **账本前缀**：侧车节点 id 必须以所属项目名前缀开头（P6 机器校验，warning；diagram-* 元节点与
   kind=meta 节点豁免）；
3. **门户纯生成**：门户目录只由 build-portal 生成/覆盖，禁手改；旧门户保留为历史（v3：旧**期**目录保留为历史）；
4. **兼容垫片**：v1 旧路径符号链接垫片属过渡措施（见 〇.3），不计为平铺违规；v3 起伞内符号链接同样跳过；
5. **校验强制**：布局校验器（lib/layout.mjs）识别 v2/v3 版式并逐条机器校验，违反即 defect。

### 〇.3 兼容与迁移（v1 → v2）

- **v1 平铺已废弃（0.9.0 塌缩，两段式废弃第一阶段）**：文件直接在 spec/ 下（无一级子目录）= v1 平铺——数据根已 v3、
  init 自 0.7.0 起直接生成 v3，完整 v1 校验链无数据可服务（Lehman 法则2 复杂度做功）。校验器检测到 v1 平铺只发一条
  warning「v1 平铺版式已废弃，请迁移至 v3（见 §〇-v3）；其详细布局校验已于 v0.9.0 停止」并直接返回（不再跑整条校验链；保持
  warning 级、exit 0 语义，不判死旧目录）；其详细布局校验已于 v0.9.0 停止。v1 旧校验链描述入 RELEASES 0.9.0 前条目史实区。
- **符号链接垫片**：旧路径符号链接垫片属过渡措施，不计为平铺违规；按废弃两段式退出

- 数据迁移（v1 目录 → v2 项目化重排）为独立一波工作，另行成文。

## 一、诊断（为什么平铺是乱象）

早期图集实测：127 个文件平铺根目录（PNG 60 / JSON 31 / HTML 30 / CSV 5 / MD 1），零子目录；同一图家族 8 件（spec + 交付物 + 4 快照 + visual-check HTML/JSON）散落根目录——检索靠文件名前缀，版本靠 .v2 后缀，交付物与规格与证据不可分。

## 二、v1 标准目录（七区制）

> 0.7.0 起 init 直接生成 v3 版式（七区 + 项目一级子目录 + state/projects.json 注册表，见 §〇-v3 与
> command-contract.md §1）；本节为 v1 单项目条款，术语定义用（v1 校验链 0.9.0 已塌缩，见 §〇.3）。
> v2 下七区保留为共享区，spec/evidence/data 按项目名隔离、artifacts 两级
> 项目/模块-日期，见 §〇.1。

    <atlas-root>/
    ├── INDEX.md        总索引（唯一入口：六层注册表 + 图清单 + 数据资产清单）
    ├── spec/           图谱规格（archify JSON，一图一文件 <diagram-id>.json）
    ├── artifacts/      交付物（HTML，<diagram-id>.html，与 spec 同名）
    ├── evidence/       视觉核查回执与快照（每图子目录 evidence/<diagram-id>/）
    ├── data/           数据资产（CSV，全行带证据；证据列双形态：文件:行号 或 git <sha>）
    ├── state/          atlas-state.json（三轴状态侧车 + 历史账本）
    ├── rulings/        裁定节点（RULINGS.md 引用台账条目，原文在台账）
    └── history/        快照与时间线（SNAPSHOT-MANIFEST.json + 版本快照）

> 证据列双形态（2026-08-15 裁定①）：`文件:行号` = 细粒度位置声称；`git <sha>`（7-40 位十六进制）= 提交级事实声称，
> 内容寻址不可变故抗漂移（行号随重构漂移，SHA 不漂）。校验器：两形态格式合法即 compliant；`git <sha>` 另做
> 二层存在性机器校验（图谱目录自身是 git 仓，或设 ATLAS_GIT_ROOT 时，逐条 `git cat-file -e`，SHA 不在仓 =
> error p5-sha-broken；无可用根不逐条报噪音，unchecked 具名披露一条）。

## 三、命名与版本纪律

> v1 条款；v2 下三区同名规则按项目内同名执行（spec/<项目>/<id>.json ↔ evidence/<项目>/<id>/），
> artifacts 改名模块-日期分组（§〇.1），一元化检查按项目内同名。

1. 一元化：一图一个稳定 diagram-id（如 demo-map）；spec/artifacts/evidence 三处同名不同后缀。
2. .vN 后缀：v1 时代禁令（版本走 git 历史）；v2 修订（2026-08-15）：登记在册的版本化图规格（如 demo-architecture.v2）属合法演进产物，降为 warning 提醒；真双份靠 P4 注册对账与人工审查兜底。
3. 证据归位：visual-check 回执/PNG 必须进 evidence/<diagram-id>/，禁与 spec/artifacts 混放。
4. 数据资产只进 data/；裁定原文只在台账（rulings/ 存引用行）。

## 四、反模式禁令（从早期图集平铺实践提炼，validator 硬门禁）

> v1 条款 P1-P5；v2 演进：P1 根目录另允许 `<项目>-add-<YYMMDD>` 门户目录；P2 在 v2 下校验
> 项目子目录内混放（spec/ 一级只允许项目子目录等）；P4 在 v2 下以项目为注册单位；
> 新增 **P6 节点前缀纪律**（§〇.2-2，warning 级，需 --sidecar 联动）。

- P1 禁平铺：根目录只允许 INDEX.md + 七区目录，出现其他文件 = error。
- P2 禁混放：spec/ 只允许 .json；artifacts/ 只允许 .html；evidence/ 只允许回执与快照。
- P3 禁双份：「副本/copy」类双份 = error；.vN 版本化规格在 v2 版式下 = warning（见 §二.2 v2 修订）；符号链接垫片一律豁免。
- P4 禁无索引：缺 INDEX.md 或 INDEX 未注册某图 = warning。
- P5 禁无证据的数据资产：data/*.csv 缺证据列 = error（继承图集纪律）；证据列双形态与 SHA 存在性二层校验见 §二（裁定①）。

> 勘误（2026-08-15）：P1 原文「八个子目录」与 §二 七区制定义矛盾，layout 校验器（lib/layout.mjs）落地时发现，已按七区 + INDEX.md 勘正。

## 六、显示契约（负责人 2026-08-15 指令：禁局部内容显示）

- R1 完整默认视图：交付 HTML 的默认首屏必须呈现完整图（gate 的 visual-check 四视口收容 pass = 完整可见的机器证明）；禁止以裁剪/局部截图作为默认呈现。
- R2 焦点章节：每图经 compile 注入 meta.views 首章「当前焦点（在途 n）」——聚焦当下开发位置，不丢全局（读者点章节即跳，返回即全览）。
- R3 焦点标记：in_progress 节点 tag=「▶ 进行中」直标在完整图上，一眼定位当前开发位置。
- 完整图与焦点由同一 spec 呈现，不存在「局部内容版本」——局部永远是从完整图中导出的视图。
